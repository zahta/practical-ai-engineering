# Docker Compose and the FastAPI AI Service

This guide explains how the repository's API, AI service, and n8n run together, how the API calls Ollama, and how to diagnose common failures.

## 1. Architecture

```text
Browser or client
      │
      ├── http://localhost:8000 ──> api (FastAPI)
      │                                │
      │                                └── http://ai-service:8000/analyze
      │                                                │
      └── http://localhost:5678 ──> n8n              ▼
                                                host Ollama
                                       http://host.docker.internal:11434
```

The `api` and `ai-service` are built from their own directories. n8n uses its published image. Only the API and n8n ports are published to the host; the AI service is reached over the Compose network.

## 2. Compose configuration

The root `compose.yaml` defines the three containers, their settings, and persistent n8n data. Key options include:

| Compose setting | Purpose |
| --- | --- |
| `services` | Defines the applications in the project |
| `build` | Builds an image from the specified directory and Dockerfile |
| `image` | Uses an existing image, such as the n8n image |
| `ports` | Maps a host port to a container port |
| `env_file` / `environment` | Supplies runtime environment variables |
| `depends_on` | Establishes service startup order |
| `volumes` | Persists data outside a container's lifecycle |
| `restart: unless-stopped` | Restarts a container unless it was explicitly stopped |

The API's development settings are read from `fastapi-basic/.env`. The AI service receives its Ollama settings from Compose:

| Variable | Default in Compose | Purpose |
| --- | --- | --- |
| `OLLAMA_BASE_URL` | `http://host.docker.internal:11434` | Ollama URL reachable from the AI container |
| `OLLAMA_MODEL` | `qwen2.5:7b` | Model name requested from Ollama |
| `OLLAMA_TIMEOUT` | `120` | AI service's Ollama request timeout in seconds |

`depends_on` controls startup order; it does not ensure that a dependency has completed initialization or is ready to serve requests.

## 3. Start and manage the project

Run these commands from the repository root:

```bash
docker compose up --build -d
docker compose ps
docker compose logs -f api
docker compose logs -f ai-service
docker compose logs -f n8n
```

`--build` rebuilds the project images, and `-d` runs services in the background. To stop containers while retaining them, use `docker compose stop`; resume them with `docker compose start`.

```bash
docker compose down
```

`down` removes the Compose containers and network. It preserves the named `n8n_data` volume by default. To remove that persistent data as well, explicitly run `docker compose down --volumes`.

## 4. Container networking: service names versus localhost

Compose services share a network and can reach each other by service name:

- From n8n, call the API at `http://api:8000`.
- From the API, call the AI service at `http://ai-service:8000`.
- From the host, use published ports such as `http://localhost:8000` and `http://localhost:5678`.
- From the AI container, the host's Ollama server is configured as `http://host.docker.internal:11434`.

Inside a container, `localhost` refers to that same container, not another Compose service or the host machine. The AI service's port is not published to the host; other containers can still access it through the Compose network.

## 5. Prepare Ollama

Ollama runs on the host and is not itself a Compose service in this repository. Install and start Ollama, then pull the model configured in `compose.yaml`:

```bash
ollama pull qwen2.5:7b
```

If you change the model, update `OLLAMA_MODEL` in Compose to match a model available to Ollama. The AI service reads its base URL, model, and timeout from environment variables.

## 6. Follow an analysis request

The API validates the body with a Pydantic model:

```json
{"text":"Explain Docker Compose."}
```

It sends the text to `POST http://ai-service:8000/analyze` using HTTPX. The AI service builds a prompt, calls Ollama's `/api/generate` endpoint with streaming disabled, and returns:

```json
{
  "result": "A concise analysis generated by the configured model.",
  "length": 23,
  "provider": "ollama",
  "model": "qwen2.5:7b"
}
```

`length` is the number of characters in the input text. The `/health` endpoint reports the configured provider and model; it is a simple service response and does not verify that Ollama is reachable.

Test the public API from the host:

```bash
curl -i -X POST http://localhost:8000/analyze \
  -H "Content-Type: application/json" \
  -d '{"text":"Explain Docker Compose."}'
```

The interactive API documentation is available at `http://localhost:8000/docs`.

## 7. Timeouts and error handling

The API calls the AI service with an HTTPX timeout of 180 seconds. The AI service allows up to 120 seconds for its Ollama call. Errors are translated into HTTP responses:

| Failure | Response from the affected service |
| --- | --- |
| Ollama returns an HTTP error | AI service returns `502 Bad Gateway` |
| Ollama cannot be reached or times out | AI service returns `504 Gateway Timeout` |
| API receives an unsuccessful HTTP response from AI service | API returns `502 Bad Gateway` |
| API cannot connect to AI service | API returns `503 Service Unavailable` |
| API's request to AI service times out | API returns `504 Gateway Timeout` |

## 8. Troubleshooting checklist

1. Run `docker compose ps` and confirm that `api`, `ai-service`, and `n8n` are running.
2. Inspect the relevant output with `docker compose logs api` or `docker compose logs ai-service`.
3. Confirm that Ollama is running on the host and that `qwen2.5:7b` has been pulled.
4. Check that the model name and Ollama URL in Compose match your local setup.
5. Use `http://ai-service:8000` for container-to-container calls, not `localhost`.
6. Rebuild after changing application dependencies or Docker build inputs:

   ```bash
   docker compose up --build -d
   ```

7. Check API validation errors separately: malformed request bodies are rejected before the AI service is called.

### Key points to remember

- Compose service names act as hostnames on the shared Compose network.
- A container's `localhost` is not the host and is not another container.
- `depends_on` orders startup but does not provide a readiness check.
- n8n's named volume keeps its data when containers are removed.
- The AI service is a real Ollama client; Ollama itself must be running on the host.
