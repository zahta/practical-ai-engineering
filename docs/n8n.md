# Build an n8n Text-Analysis Workflow

This tutorial connects an n8n Webhook to the repository's FastAPI endpoint. The workflow receives text, validates it, calls the API, and returns either the analysis or a client error.

## 1. Start the services

From the repository root:

```bash
docker compose up --build -d
```

Open n8n at [http://localhost:5678](http://localhost:5678). Complete its initial local setup if prompted. The API's interactive documentation is available at [http://localhost:8000/docs](http://localhost:8000/docs).

The workflow runs inside the n8n container, so its API URL must use the Compose service name `api`, not `localhost`:

```text
http://api:8000/analyze
```

## 2. Understand the workflow

Create and connect these nodes:

```text
Webhook → IF
           ├── true → HTTP Request → Respond to Webhook (success)
           └── false ──────────────→ Respond to Webhook (400)
```

- **Webhook** starts the workflow when an HTTP request arrives.
- **IF** checks that the supplied text is not empty.
- **HTTP Request** sends the text to the FastAPI service.
- **Respond to Webhook** returns the workflow result and chosen HTTP status to the caller.

## 3. Configure the Webhook

Set the Webhook node to:

| Setting | Value |
| --- | --- |
| HTTP Method | `POST` |
| Path | `analyze-text` |
| Authentication | `None` for local practice only |
| Respond | `Using Respond to Webhook Node` |

The incoming request body should be JSON:

```json
{"text":"Explain Docker Compose."}
```

With the default Webhook output, the field is available as `{{$json.body.text}}`.

## 4. Validate the text

Configure the IF node with a string condition that checks whether `{{$json.body.text}}` is not empty.

Connect the Webhook output to the IF node. Route the `true` output to the HTTP Request node and the `false` output directly to a separate Respond to Webhook node.

This simple check rejects an empty string. If the input field is missing or has the wrong type, handle that as an invalid request too when adapting the workflow.

## 5. Call the FastAPI endpoint

Configure the HTTP Request node:

| Setting | Value |
| --- | --- |
| Method | `POST` |
| URL | `http://api:8000/analyze` |
| Send Body | Enabled |
| Body Content Type | JSON |
| Body field `text` | `={{ $json.body.text }}` |

Use the node's JSON/body-parameter editor to add a `text` property whose value is the n8n expression shown above. The API responds with the generated result and metadata, for example:

```json
{
  "result": "A concise analysis generated by the configured model.",
  "length": 23,
  "provider": "ollama",
  "model": "qwen2.5:7b"
}
```

## 6. Return a response to the caller

Connect the HTTP Request node to the success Respond to Webhook node. Configure it to return the incoming JSON data with status code `200`.

Connect the IF node's `false` output to the other Respond to Webhook node. Return a JSON body such as:

```json
{"error":"Text must not be empty"}
```

Set its response code to `400`. Ensure both response nodes are connected to their intended paths.

## 7. Test the workflow

### Test URL

In the Webhook node, select **Listen for Test Event**, then send a request from the host:

```bash
curl -i -X POST "http://localhost:5678/webhook-test/analyze-text" \
  -H "Content-Type: application/json" \
  -d '{"text":"Run AI automation through n8n."}'
```

Inspect the execution in n8n. If the Webhook responds immediately rather than waiting for the response node, verify that **Respond** is set to **Using Respond to Webhook Node**.

### Production URL

Save and activate or publish the workflow, then use:

```bash
curl -i -X POST "http://localhost:5678/webhook/analyze-text" \
  -H "Content-Type: application/json" \
  -d '{"text":"Run AI automation through n8n."}'
```

The test URL uses `/webhook-test/` and requires the Webhook node to listen for an event. The production URL uses `/webhook/` and requires the workflow to be active.

### Check both outcomes

Valid input should return the FastAPI analysis with HTTP `200`:

```bash
curl -i -X POST "http://localhost:5678/webhook/analyze-text" \
  -H "Content-Type: application/json" \
  -d '{"text":"Hello from n8n."}'
```

An empty string should follow the false path and return HTTP `400`:

```bash
curl -i -X POST "http://localhost:5678/webhook/analyze-text" \
  -H "Content-Type: application/json" \
  -d '{"text":""}'
```

If a request reaches the API but does not reach the AI service, inspect the execution in n8n and the API logs:

```bash
docker compose logs -f api
docker compose logs -f ai-service
```

## 8. Security and operational notes

- `Authentication: None` and the Compose setting `N8N_SECURE_COOKIE: "false"` are for local development, not a public deployment.
- Protect public Webhooks with authentication and HTTPS, and validate all untrusted input.
- The n8n container reaches FastAPI at `http://api:8000`; `localhost` inside n8n points back to n8n.
- An API or Ollama failure is separate from the empty-text validation path. Review the execution and service logs to diagnose it.
- n8n stores its state in the `n8n_data` named volume.
